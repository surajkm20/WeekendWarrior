AirLLM RAG — System Architecture

Server-less LLM · Layer-Streamed Inference · Local Embeddings · Private Documents

⚠ Hardware note: AirLLM streams model layers from disk instead of loading the whole model into memory, which is what lets a 70B model run without 140GB of RAM. It targets CUDA GPUs — on a machine without an NVIDIA GPU it falls back to CPU-only execution, which is far slower. There is also no native token streaming: the model returns a complete answer in one blocking call.

2. Ingestion Flow — python ingest.py
1
Load Documents from ./docs/
pdfplumber extracts prose text + tables per PDF page (tables formatted as pipe-separated rows so columns stay unambiguous). DirectoryLoader also picks up .docx and .txt. Every document carries metadata: source filename + page number.
2
Split into Chunks
RecursiveCharacterTextSplitter splits text into chunks of 1500 chars with 300 char overlap. Overlap prevents losing context at boundaries. Tries to split on paragraphs → sentences → words.
3
Generate Embeddings Locally
Each chunk is embedded with sentence-transformers/all-mpnet-base-v2, running directly in-process (no server, unlike AirLLM's generation step). Returns a 768-dim vector representing the semantic meaning of that chunk.
4
Store in ChromaDB
Vectors + original text + metadata are persisted to ./vectorstore/ on disk. ChromaDB uses HNSW index for fast similarity search. This step only runs once per document set.
3. Query Flow — what happens when you ask a question
1
User types a question in the browser
Chainlit captures the message and sends it to on_message() in app.py via WebSocket.
2
Contextualize the Question (if chat history exists)
Follow-up questions are rephrased into standalone questions by running the contextualize prompt through AirLLM. This blocking call executes on a background thread so it doesn't freeze the WebSocket event loop.
3
Hybrid Retrieval: BM25 + Vector Search
The standalone question is run through BM25 (keyword match) and ChromaDB vector similarity in parallel. Results are merged with Reciprocal Rank Fusion into a candidate set of TOP_K_RESULTS × 4 chunks.
4
Cross-Encoder Re-Ranking
Each candidate chunk is scored against the query with cross-encoder/ms-marco-MiniLM-L-6-v2 — a model that reads the query and passage together for a much more precise relevance score than embedding similarity alone. Only the top TOP_K_RESULTS (default 6) survive.
5
Build the Prompt
The answer prompt is assembled with 3 parts: chat_history (last 6 turns) + context (re-ranked chunks) + question (original user question). Strict instruction: answer ONLY from the context.
6
AirLLM Generates the Answer (one blocking call)
The prompt is tokenized and run through model.generate(), which streams the model's layers from disk one at a time. There is no native token-by-token output — the full answer comes back at once, then app.py streams it word-by-word to the browser to mimic live typing.
7
Show Source Citations + Save History
Source filenames and page numbers are appended below the answer. The question + answer are saved to chat_history (capped at last 6 turns) for use in the next question.

5. Configuration — config.py

Models

  • LLMMeta-Llama-3.1-70B-Instruct
  • LLM RuntimeAirLLM (compression=4bit)
  • Embedding Modelall-mpnet-base-v2
  • Re-rankerms-marco-MiniLM-L-6-v2

Chunking & Retrieval

  • Chunk Size1500 chars
  • Chunk Overlap300 chars
  • Candidate SetTop-K × 4 (BM25 + vector)
  • Top-K Results6 chunks after re-ranking
  • History WindowLast 6 turns

Storage Paths

  • Documents folder./docs/
  • Vector store./vectorstore/
  • Collection nameairllm_docs

Hardware

  • Best onNVIDIA GPU (CUDA)
  • FallbackCPU-only (much slower)
  • Model serverNone — in-process
  • Internet requiredOnly for first model/doc download

7. Setup & Run Commands

One-time Setup

cd AirLLM_RAG
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
huggingface-cli login   # required for gated models like Llama 3.1

Every Time You Use It

source .venv/bin/activate
python ingest.py        # only needed after adding new docs
chainlit run app.py     # open http://localhost:8000
                         # first message is slow: AirLLM shards the model to disk
